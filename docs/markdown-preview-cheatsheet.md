# Markdown プレビュー チートシート

AI エージェントが書いた設計メモ・作業ログ・`docs/` の md を「読むだけ」のための 2 つのビューア。
どちらも aqua 管理の Go 単一バイナリで、**用途で使い分ける**。

| ツール | 出す先 | 起動キー | 向いている場面 |
| --- | --- | --- | --- |
| [glow](https://github.com/charmbracelet/glow) | 端末内の TUI | `<prefix> shift+m` | エージェントのペインを見ながら、隣で仕様書をざっと読む |
| [mo](https://github.com/k1LoW/mo) | 手元 PC のブラウザ | `<prefix> m` | mermaid 図・数式・全文検索・保存即反映が要る |

> 起動キーはどちらも herdr の popup（[herdr チートシート](herdr-cheatsheet.md#カスタムコマンドpopup)）。
> **よく使う方（ブラウザ）を打ちやすい `m` に置いている。**

- **導入**: aqua で管理（`dot_config/aquaproj-aqua/aqua.yaml` の `charmbracelet/glow` / `k1LoW/mo`）
- **glow の設定**: 既定のまま（設定ファイルは配っていない）。変えたいときは `glow config`
- **mo の設定**: 既定のまま。セッション（開いているファイル群）は mo 自身が保存・復元する

> どちらも**閲覧専用**。編集は nvim で行う（glow は `e` で `$EDITOR` に渡せる）。

## glow（端末内 TUI）

### 起動

herdr の popup に割り当ててある。**フォーカス中ペインの作業ディレクトリ**で開くので、
エージェントを動かしているリポジトリのまま一覧が出る。

| 起動方法 | 動作 |
| --- | --- |
| `<prefix> shift+m` | herdr の popup で開く（[herdr チートシート](herdr-cheatsheet.md#カスタムコマンドpopup)） |
| `glow` | カレントディレクトリ以下の md を一覧する TUI。**git リポジトリ内ならリポジトリ全体**を探す |
| `glow FILE.md` | 1 ファイルを整形して標準出力へ流す（TUI にはならない） |
| `glow -p FILE.md` | 整形結果をページャ（既定 `less -r`）で開く |
| `cat FILE.md \| glow -` | 標準入力を整形する |
| `glow -w 80 FILE.md` | 折り返し幅を指定する |

> popup は**中のコマンドが終了したときだけ**閉じる。glow は `q`（gitui / yazi と同じ）。

### キーバインド: ファイル一覧

| キー | 動作 |
| --- | --- |
| `Enter` | 開く |
| `j` / `k`、`↑` / `↓` | 選択を移動 |
| `g` / `home`、`G` / `end` | 先頭 / 末尾へ |
| `h` / `l`、`←` / `→` | ページ送り |
| `Tab` / `Shift+Tab` | セクション切替 |
| `/` | 絞り込み（フィルタ中は `Esc` で解除） |
| `e` | `$EDITOR`（= nvim）で開く |
| `r` | 一覧を取り直す |
| `?` | ヘルプの開閉 |
| `q` | 終了（= popup が閉じる） |

### キーバインド: 文書表示

| キー | 動作 |
| --- | --- |
| `f` / `PgDn`、`b` / `PgUp` | 1 画面送り / 戻し |
| `d` / `u` | 半画面送り / 戻し |
| `g` / `home`、`G` / `end` | 先頭 / 末尾へ |
| `Esc`、`h`、`←` | 一覧へ戻る |
| `c` | 本文をクリップボードへコピー（OSC 52 + ネイティブ） |
| `e` | `$EDITOR`（= nvim）で開く。**今見ている行**にカーソルが合う |
| `r` | 読み直す |
| `?` | ヘルプの開閉 |
| `q` | 終了（= popup が閉じる） |

## mo（手元 PC のブラウザ）

`mo` はバックグラウンドで HTTP サーバを立て、ブラウザを開く。**2 回目以降の実行は同じ
セッションにファイルを足す**（サーバは立て直さない）。

### 起動

herdr の popup に割り当ててある。`mo` は引数が無いと前回セッションを復元するだけなので、
popup では橋渡しスクリプト `~/.local/bin/herdr-mo` が**ファイル選択 UI を挟む**。

| 起動方法 | 動作 |
| --- | --- |
| `<prefix> m` | herdr の popup で md を選び、`mo` へ渡す。**リポジトリごとのグループ**に入る（下記「`<prefix> m` の中身」）。選択 UI は `Tab` で複数選択（まとめて 1 つのグループへ入る）、`Ctrl-R` はファイルを選ばずにタブを開き直す、`Ctrl-G` は `.gitignore` 対象も含めた一覧と行き来する |
| `mo` | 前回セッションを復元してブラウザを開く（**ファイルは足せない**） |
| `mo FILE.md ...` | ファイルを開く / 起動中のセッションへ足す |

#### `<prefix> m` の中身（herdr-mo）

chezmoi ソースは `dot_local/bin/executable_herdr-mo`。やっていることは 3 つだけ。

1. `fd` で md を一覧する。範囲は **glow と揃えてあり、git リポジトリ内ならリポジトリ全体**、
   外なら cwd 以下（popup はフォーカス中ペインの作業ディレクトリで開く）。既定では
   `.gitignore` などの無視設定に従う（`Ctrl-G` で外せる。下の「`Ctrl-G`」）
2. `fzf --multi` で選ばせる。プレビューは `glow`、`Tab` で複数選択、`Esc` で何もせず終了、
   **`Ctrl-R` はファイルを選ばずにタブを開き直す**（下の「`--open` と `Ctrl-R`」）、
   **`Ctrl-G` は無視設定を外した一覧と行き来する**（下の「`Ctrl-G`」）。
   `Tab` / `Ctrl-R` / `Ctrl-G` は fzf のヘッダーにも出している。`Space` に割り当て直していないのは、
   fzf のスペース区切り AND 検索（`docs cheat` で両方を含む行に絞る）を潰さないため

> **`--layout=reverse` を付けている理由（`Tab` 連打で複数選ぶため）**: fzf の `tab` は
> `toggle+down` だが、**既定レイアウトはプロンプトが下でリストが上向きに伸びる**ため、
> カーソルの初期位置（先頭項目）が既に最下段で `down` が効かない。結果 `Tab` を連打しても
> 同じ行をトグルし続け、**1 件しか選べない**（既定のままで複数選べるのは `Shift-Tab` =
> `toggle+up` だけ）。`--layout=reverse` にするとリストが上から下へ並び、カーソルが最上段から
> 下へ進むので `Tab` 連打で順に選べる。選んだ md は**まとめて同じグループへ**入る。
3. 選ばれたファイルを `mo --target <リポジトリ名> --open` に渡す

`mo` は自分でバックグラウンドへ回るので、**選び終わると popup は閉じ**、表示は手元 PC の
ブラウザ側で続く。`$BROWSER` が無いときだけ警告を出して `[Enter]` で止まる（下の「落とし穴」）。

**`Ctrl-G`（`.gitignore` 対象も出す）**: `fd` は既定で `.gitignore` などの無視設定に従うため、
**コミットしないが読みたい md** — `.superpowers/` や `docs/superpowers/` に溜まるエージェントの
作業ログ（spec / plan / task report）— が一覧に出ない。かといって常に全件にすると、
`.terraform/modules` や `node_modules` の README が数百件流れ込むリポジトリがある。そこで
**既定は無視設定に従い、要るときだけ `Ctrl-G` で外す**。もう一度押すと戻る。今どちらを見ているかは
プロンプトの `[全件]` で分かる（`mo/<リポジトリ名> [全件]>`）。

> 実装は fzf の `transform` アクション。fzf 自身はトグルの状態を持たないので、`$FZF_PROMPT`
> （押された時点のプロンプト）に `[全件]` が入っているかを状態として使い、`reload` +
> `change-prompt` + `change-header` を返している。

**`--open` と `Ctrl-R`（ポートフォワードの張り直し）**: `mo` は**既存グループへファイルを
足すだけのときブラウザを開かない**。開かないということは `$BROWSER`（= `portfwd-open`）が
呼ばれず、手元 PC の portfwd へ通知が飛ばないということで、リレーが畳まれた後に `<prefix> m`
を叩いても張り直されない（`mo --shutdown` でサーバを立て直すまで直らない）。そのため
`herdr-mo` は常に `--open`（`Always open browser (even when adding to existing group)`）を
付けて呼ぶ。張り直したいだけで開くファイルが無いときは、選択 UI で **`Ctrl-R`** を押せば
ファイルを足さずに通知だけを投げ直せる。

**`--port` を付けている理由**: `mo` のサーバは**ポート単位でマシン全体に 1 つ**しか無い。
`--bind localhost` でも loopback にユーザ境界は無いので、複数ユーザがいるホストで全員が既定の
6275 を使うと、**先にサーバを立てた人の `mo` へ後から叩いた全員がぶら下がる**。相手が開いた
md の中身が自分のブラウザに出て、こちらから相手のサーバを `--shutdown` することもできる。
そこでポートを `~/.local/bin/mo-port` がユーザごとに決める（既定は `6275 + (uid - 1000)`。
`MO_PORT` があればそれを優先するので、衝突したら `~/.env` に書いてずらす）。`herdr-mo` は
起動前に `/proc/net/tcp` でそのポートの listen 主が自分かを確かめ、他人なら理由を出して
止まる（`/proc` の無い macOS では確認を省く。単独ユーザなので取り違えが起きない）。素の `mo` も `~/.local/bin/mo`（zsh 関数ではなくスクリプト。シェルの rc を経由しない
起動経路にも届かせるため）が `--port` を渡すので、常に同じポートに揃う。
迂回したいときは `--port` を明示するか `MO_PORT` を設定する。

**`--target` を付けている理由**: `mo` のセッションは消すまで積み上がるため、既定グループへ
入れ続けるとサイドバーが数百件に膨らんで目的の md を探せなくなる。グループを分ければ
リポジトリごとに独立したサイドバーと URL（`http://localhost:<自分のポート>/<リポジトリ名>`）
になり、
別のリポジトリで作業してもサイドバーが混ざらない。グループ名は git リポジトリのトップ
（外なら cwd）のディレクトリ名で、URL に使えない文字は `-` へ潰す。`fzf` のプロンプトに
`mo/<リポジトリ名>> ` と出るので、どのグループへ入るかは選ぶ前に分かる。

#### 直接叩く

```sh
mo README.md                 # 1 ファイル
mo docs/                     # ディレクトリ内の .md をまとめて
mo spec.md --target design   # 名前付きグループに入れる
cat notes.md | mo            # 標準入力から
mo docs/ --watch             # ファイル追加を監視する
```

| オプション | 既定 | 意味 |
| --- | --- | --- |
| `--port` / `-p` | `6275`（`~/.local/bin/mo` スクリプトが `mo-port` の値を渡す） | listen ポート |
| `--bind` / `-b` | `localhost` | bind アドレス |
| `--open` / `--no-open` | open | ブラウザを開くか |
| `--watch` / `-w` | off | ファイルの追加を監視する |
| `--foreground` | off | バックグラウンドに回さず前面で動かす |
| `--status` | — | 起動中のサーバを表示 |
| `--restart` / `--shutdown` | — | サーバの再起動 / 停止 |
| `--close` | — | 指定したファイルを開くのではなくセッションから外す |
| `--clear` | — | 保存済みセッションを消す（**全グループ**。確認プロンプトが出る） |

主な表示機能: GitHub 風 Markdown + シンタックスハイライト（Shiki）/ **mermaid**（クリックで拡大）/
数式（KaTeX）/ ダーク・ライト切替 / ファイル名と本文の全文検索 / **保存すると即反映**（live reload）/
サイドバーのツリー表示。

### なぜ手元 PC のブラウザで開くのか

mo は `pkg/browser` 経由で `xdg-open` を呼び、**`xdg-open` は `$BROWSER` を優先する**。
SSH 先では portfwd 対象セッションで `$BROWSER=~/.local/bin/portfwd-open` になっているため、
URL がそのまま手元 PC へ渡る（[portfwd チートシート](portfwd-cheatsheet.md)）。手元の
macOS で直接叩いたときは、そのまま既定のブラウザが開く。

```
mo docs/
  └─ xdg-open → $BROWSER=portfwd-open → 手元 PC の daemon
       1. http://localhost:6275/ を「ローカルのページ」と判定
       2. 手元の 127.0.0.1:6275 を listen し、SOCKS 経由で SSH 先の 6275 へ中継
       3. 手元 PC の既定ブラウザで開く
```

### 落とし穴

- **放置しても切れない。切れるのは `mo` を終了させたときと、ssh が長く戻らないとき**。
  portfwd のページリレーは 60 秒ごとにサーバ側の 6275 を叩いて生存を確かめ、`mo` が落ちて
  いたら畳む。ssh が切れている間は 90 分まで維持するので、昼休みで PC がスリープした程度なら
  戻ってきたタブがそのまま使える。畳まれた後でも **`<prefix> m` → `Ctrl-R` で張り直せる**
  （サーバ自体は生きているので、開いているファイルは失われない）。
- **SSH 先で portfwd 非対象のセッションだと開かない**。`LC_PORTFWD_HOST` が来ていないと
  `$BROWSER` が設定されず、`xdg-open` も SSH 先にブラウザを見つけられない。ssh 設定の
  オプトインを確認する（[portfwd チートシート](portfwd-cheatsheet.md)）。
- **ポートを揃えると他人の mo にぶら下がる**。`mo` のサーバはポート単位でマシン全体に 1 つ
  しか無く、loopback にユーザ境界は無い。複数ユーザのホストで既定の 6275 のままだと、先に
  立てた人のサーバへ全員が相乗りし、**相手が開いた md が自分のブラウザに出る**
  （`--shutdown` も相手に効く）。そこで `mo-port` がユーザごとのポートを決め、`herdr-mo` が
  listen 主を確かめて他人のものなら止める。それでも**同じポートを知っている他のローカル
  ユーザは接続できる**（`mo` に認証は無い）ので、共有ホストでは見せたくない md を開かない。
- **セッションは消さない限り積み上がる**。`mo` は開いたファイルを保存・復元するので、
  同じグループを開き続ければサイドバーは伸び続ける。`<prefix> m` は `--target` で
  リポジトリごとに分けるため混ざりはしないが、1 つのリポジトリで溜まったものは消えない。
  減らすなら `mo --close FILE.md ...` で個別に外す。全部畳むなら `mo --shutdown` →
  `mo --clear` だが、これは**グループを問わず保存済みセッションごと**消える
  （確認プロンプトが出る。非対話で叩くと `mo: canceled` になり何もしない）。
  なお `mo` を素で叩くと既定グループ（`http://localhost:<自分のポート>/`）へ入り、
  `<prefix> m` のグループとは別扱いになる。
- **popup は herdr サーバ起動時の環境を継承する**。portfwd 非対象のセッションで herdr を
  起動していると、`<prefix> m` から呼ばれた `mo` に `$BROWSER` が渡らない。`herdr-mo` は
  このとき警告と URL を出して止まるので、portfwd 対象のセッションで `herdr server stop` →
  `herdr` と起動し直す（`herdr server reload-config` では環境は入れ替わらない）。

## 動かないとき

`<prefix> m` / `<prefix> shift+m` を押しても何も起きない、`mo: command not found` /
`fzf コマンドが見つかりません` のときは、aqua の導入が済んでいない。`chezmoi apply`
（= `aqua i` が走る）を実行する。`<prefix> m` は mo に加えて fzf・fd・glow も使う。
